# create-pr

현재 브랜치가 base 브랜치 대비 무엇을 바꿨는지 읽고, 프로젝트 언어에 맞는 템플릿으로 PR을 만든다. 이 스킬은 fork된 서브 에이전트에서 돌아가므로 메인 대화로 되물을 수 없다. 사용자가 PR 생성을 요청한 것 자체가 승인이니, 아래 중단 조건에 해당하지 않으면 끝까지 진행하고 결과(PR URL)만 보고한다.

## 절차

### 1. 상태 확인

```bash
git branch --show-current
git status --short
git remote -v
gh auth status
gh repo view --json defaultBranchRef,isFork,parent,nameWithOwner
```

- base 브랜치는 `defaultBranchRef`(보통 `main`)다. 사용자가 다른 base를 말했으면 그쪽을 쓴다.
- 현재 브랜치가 base와 같으면 중단한다. base에 직접 PR을 만들 수 없고, 브랜치를 임의로 만들면 사용자의 작업 흐름을 어지럽힌다. 브랜치를 먼저 만들어 달라고 알린다.
- `gh`가 없거나 인증이 안 되어 있으면 중단하고 `gh auth login`이 필요하다고 알린다.
- 이미 이 브랜치의 열린 PR이 있는지 `gh pr list --head <브랜치> --state open`으로 본다. 있으면 새로 만들지 말고 그 URL을 알린다. 중복 PR은 리뷰를 분산시킨다.
- 커밋되지 않은 변경이 있으면 PR에 포함되지 않는다는 점을 최종 보고에 한 줄로 알린다. 커밋은 대신 만들지 않는다.

### 2. 변경 내용 파악

```bash
git fetch origin <base>
git log origin/<base>..HEAD --oneline
git diff origin/<base>...HEAD --stat
git diff origin/<base>...HEAD
```

- 비교 범위는 `origin/<base>...HEAD`(세 점)다. base가 그 사이 앞서갔어도 이 브랜치가 도입한 변경만 보이기 때문이다.
- 커밋이 0개면 PR할 게 없으니 중단하고 알린다.
- diff가 매우 크면 `--stat`과 커밋 메시지로 큰 그림을 잡고, 핵심 파일만 읽는다. PR 본문은 변경 목록의 복붙이 아니라 "왜, 무엇이 달라지는가"를 전달해야 한다.
- 이 프로젝트처럼 `AGENTS.md`/`CLAUDE.md`에 완료 전 검증 명령(테스트, 린트, 빌드)이 정의돼 있으면 읽어 두었다가, 실제로 돌려 본 것만 본문의 테스트 항목에 체크한다. 돌리지 않은 걸 통과했다고 쓰면 리뷰어가 속는다.

### 3. 템플릿 언어 결정

PR 본문 언어는 "이 프로젝트의 소통 언어"를 따른다. 외부 기여자가 한국어 PR을 받거나, 한국 팀이 영어 PR을 받으면 읽기 어렵기 때문이다. 아래 순서로 판단하고, 먼저 확정되는 신호를 쓴다.

1. **사용자의 명시적 지시** — "영어로", "in English", "한국어로" 등.
2. **저장소가 지정한 템플릿** — `.github/pull_request_template.md`(또는 `PULL_REQUEST_TEMPLATE/`)가 있으면 그 파일이 곧 템플릿이다. references의 템플릿 대신 그것을 채운다(언어도 그 파일을 따른다).
3. **프로젝트 신호** — 아래를 종합한다.
   - 최근 커밋 메시지(`git log -20 --format=%s`)와 이미 머지된 PR 제목(`gh pr list --state merged --limit 10`)의 언어
   - `README.md`, `AGENTS.md`, `CONTRIBUTING.md`의 주 언어와 "소스 주석/커밋은 한국어로" 같은 명시 규칙
   - 이슈·PR 코멘트 언어
4. **판단이 갈리면** 한국어 문자가 절반 이상이면 한국어, 아니면 영어. 해외 오픈소스(fork의 upstream 저장소로 PR을 보내는 경우 포함)는 기본적으로 영어다. 소유자가 한국 팀이라도 upstream이 영어 프로젝트면 영어를 쓴다.

결정한 언어와 근거를 최종 보고에 한 줄로 남긴다. 사용자가 틀렸다고 판단하면 바로 고칠 수 있게 하기 위해서다.

템플릿 파일:

| 언어 | 파일 |
|---|---|
| 한국어 | `references/template-ko.md` |
| 영어 | `references/template-en.md` |

결정된 언어의 파일만 읽는다.

### 4. 제목과 본문 작성

**제목**
- 커밋 컨벤션과 같은 형식 `<type>: <요약>`을 쓴다(`feat|fix|refactor|chore|docs|test`). 커밋이 여러 개여도 PR 전체를 대표하는 type 하나를 고른다.
- 언어는 본문과 같다. 한국어는 명사형 종결(~추가, ~수정), 영어는 명령형 현재(Add, Fix)로 쓰고, 70자 안팎으로 마침표 없이 쓴다.
- 브랜치가 단일 커밋이면 그 커밋 메시지를 다듬어 재사용해도 된다.

**본문**
- 템플릿의 섹션 구조를 유지하되, 해당 없는 섹션은 지우지 말고 "없음"/"N/A"로 둔다(리뷰어가 누락이 아닌 의도임을 알 수 있다).
- 관련 이슈가 있으면(브랜치명, 커밋 메시지의 `#123`) `Closes #123`으로 연결한다. 추측으로 이슈 번호를 만들지 않는다.
- UI 변경이면 스크린샷 자리를 남기고, 직접 첨부할 수 없다면 그렇다고 최종 보고에 알린다.
- 하네스가 PR 설명 끝에 붙이라고 지정한 attribution이 있으면 본문 맨 끝에 그대로 붙인다.

### 5. 푸시하고 PR 생성

```bash
git push -u origin HEAD        # 아직 upstream이 없거나 로컬이 앞서 있을 때
gh pr create --base <base> --title "<제목>" --body-file <본문 파일>
```

- 본문은 스크래치패드(임시 디렉터리)에 파일로 쓰고 `--body-file`로 넘긴다. `--body "..."`는 백틱·`$`·줄바꿈에서 셸이 내용을 망가뜨린다.
- 푸시는 현재 브랜치만 한다. `--force`는 쓰지 않는다. 거절되면 원인(원격이 앞서감 등)을 알리고 멈춘다. 사용자의 커밋을 덮어쓰는 것은 되돌릴 수 없다.
- 사용자가 요청하지 않았다면 `--draft`는 쓰지 않는다. 사용자가 "초안으로"라고 하면 쓴다.
- fork 저장소에서 upstream으로 보낼 때는 `--repo <upstream>`과 `--head <fork-owner>:<branch>`가 필요한지 `gh repo view`의 `parent` 정보로 확인한다.
- 비밀값(`.env`, 키)이 diff에 보이면 푸시하지 않고 중단한다. 공개된 비밀값은 회수할 수 없다.

### 6. 최종 보고

메인 대화로 돌아가는 유일한 출력이므로 짧고 완결되게 쓴다.

- PR URL
- 제목, base ← head
- 사용한 템플릿 언어와 근거 한 줄
- 알릴 것(있을 때만): 커밋되지 않은 변경, 돌리지 않은 검증, 스크린샷 미첨부, 건너뛴 이슈 연결

## 중단 조건 요약

아래에서는 PR을 만들지 않고 이유와 다음 행동을 알린다.

- 현재 브랜치가 base와 같음
- base 대비 커밋이 없음
- `gh` 미설치 또는 미인증
- diff에 비밀값이 있음
- 푸시가 거절됨
- 이미 열린 PR이 있음(URL을 알리는 것으로 끝)
